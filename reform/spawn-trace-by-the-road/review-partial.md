## 2. この表をそのまま信じてはならない(教主の実測による反証)

**基準線が `20 passed, 1 failed` である。** 壊す前から赤い。
だが教主が単独走行で測った本体は:

```
$ cd <pd-trace> && node tests/paradise.test.js
Paradise self-test: 306 passed, 0 failed        ← 赤ゼロ
```

**基準線が汚染された台の上で「鳴った/鳴らず」を数えている。**
恒常的に赤い 1 本が全行に現れており(表の全項目に
`✗ 証跡ゼロの走行は complete へ到達できない` が出ている)、
これは破壊の結果ではなく**台の状態**である。

さらに決定的なこと —— **D12 と D16 は、教主が自らの手で壊して鳴らせている**:

```
D12 相当(traceChecked を落とす):
  $ node tests/paradise.test.js
  Paradise self-test: 305 passed, 1 failed
    ✗ spawn trace: contract の CLI は run 無しで証跡を照合したと名乗らない (第37条)

D16 相当(sources 片方を消す):
  $ node tests/paradise.test.js
  Paradise self-test: 304 passed, 2 failed
    ✗ spawn trace: 採取器は二系統を必ず名乗る (M1/第44条)
    ✗ spawn trace: 拾えなかったときに黙って壊れない (第50条d)
```

**同じ破壊が、教主の台では鳴り、神官の台では鳴らなかった。**
神官の破壊は `PATCH-MISS` を 2 件自認しており(D1/D2)、
残り 8 件も**同じく的を外していた可能性が高い**。

> **これは第二幕の則D がそのまま再来した形である。**
> 「壊したつもりで壊れていない破壊試験は、緑の買収である」——
> 今回は逆向きに効いた:**壊れていない破壊が『門が鳴らない』という
> 偽の赤信号を生んだ。** 赤も緑も、まず測り方を疑え。

## 3. それでも残る本物の疑い(次のセッションが最初に手を付けるべきもの)

台が汚れていても、**D17 / D18 が指す欠陥そのものは実在しうる**。
教主はこの 2 件を**自分の手では検証していない**。憶測で緑と呼ばない(第16条)。

| # | 疑い | なぜ重いか |
|---|---|---|
| **D17** | 階梯B(時刻窓・役割名の示唆)を自動で `observed` に刻んでも門が鳴らないのではないか | design §3.3 が**最も強く禁じた**もの。**嘘の緑は no-trace より悪い**(第5条)。この境界が門に守られていないなら、採取器は自分で穴を開けられる |
| **D18** | 候補が 2 件以上ある曖昧な相でも刻んでしまう道が塞がれていないのではないか | 第51条(b)「判定不能なときは engine は手を出さず人に問え」の同型。曖昧を engine が独断で解けば二重発令と同じ病 |
| D14 | 子ログ実在検査を外しても鳴らないのではないか | 「鎖が実在する」が `observed` の根拠。外して鳴らないなら根拠が門に守られていない |
| D20 | 階梯A のパス一致規則を殺しても鳴らないのではないか | 唯一の自動適用規則。殺して鳴らないなら採取器の中核が無防備 |

### 次に打つべき手順(汚染を避けた形)

```bash
# 1. 単独走行を確保する(則E: 他の走者と同時に測らない)
#    worktree を切り、他の破壊台(pd-brk / pd-probe / pd-bs)を先に片づける
# 2. 破壊が「効いたか」を必ず実物で確かめてから、門を走らせる
#    (grep -c で対象行の消失を確認 → 振る舞いを 1 コマンド叩いて確認 → それから門)
# 3. D17/D18/D14/D20 を 1 件ずつ、単独で走らせる
```

**壊した後に「何も変わっていない」ことを先に証明せよ。門を疑うのはその後である。**
