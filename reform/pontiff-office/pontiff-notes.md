## 観測1 — 教主は三度、同じ形で沈黙した(実測)

本走行(reform/pontiff-office)の最中、教主は**三度**「次を発令する」と述べ、
**実際には delegate_task を呼ばずに turn を終えた**。神が三度とも気づいて叩き起こした。

| # | 教主が書いたこと | 実際 | 神の言葉 |
|---|---|---|---|
| 1 | 「requirements 枢機卿へ第二波を発令する」 | 投げていない | 「動いてる?」 |
| 2 | 「次は prove ——」 | 投げていない | 「うごいていますか。」 |
| 3 | 「次は quality —— review・security・docs を並列で」 | 投げていない | 「またまたまたとまっている」 |

**未来形で書いた瞬間に、教主はそれを済んだこととして扱っている。**
MAST (arXiv:2503.13657) FM-2.6「推論と実行の不一致」であり、第27条が名指しした穴の
**裏面**である。第27条は「委譲すると述べて自分でやる」を塞いだ。これは
**「委譲すると述べて誰もやらない」**である。

### なぜ本PRはこれを塞げていないか

第52条が建てた門は `conclave.markDone` の内側に立つ。すなわち**相が done になる時**
にしか鳴らない。序列1を宣言して誰も呼ばず、**done にも到達しない**沈黙は、
門の視野に一度も入らない。

- 教主が**手を動かしすぎた**こと → 測られる(files/churn/bytes)
- 教主が**何もしないまま止まった**こと → **測られない**

`conclave.js status` は「▶ 走行中」を表示し続けるが、**それが何分続いているかを
誰も裁かない**。神が番人をやっている状態である。第44条(死んだ道具は無害ではない)の
裏面: **鳴らない番人は、番人が居ないことより見つかりにくい。**

### reflect が答えるべき問い

- `wave` を返した(=発令書を渡した)のに、**一定時間 `dispatch` の証跡が現れない相**を
  機構が鳴らせるか。`spawn-trace` は既に `dispatchedAt` を持っている。
- それは新しい engine か、既存 `conclave.js status` / `pulse.js` / `daily-guard.js` の
  拡張か。**重複を作るな**(第12段の掟)。
- 「教主が考えている時間」と「教主が忘れた沈黙」をどう区別するか。区別できないなら
  閾値は何を根拠に置くか(第52条の閾値は実測から導いた。ここも同じ作法で)。
- **偽陽性を先に考えよ**: 神との対話中・長い相の待機中に鳴れば、この門は騒音になる。

## 観測2 — 教訓が隣の部屋で同じ穴を開けた

quality 枢機卿の審査が出した BLOCK(B-1)は、`spawn-trace.measure()` が git の失敗を
`null` に潰し、`judge()` がそれを**「変更ゼロ」**と読んで序列3を無条件に緑にする
fail-open であった。教主が非git ディレクトリで再現済み:

```
measure = {files:0, churn:0, bytes:0, measurable:true}
judge   = {ok:true, verdict:"green", state:"序列3",
           lines:["序列3: 教主の手 (files=0/2 churn=0/50 bytes=0/4096)"]}
```

**皮肉はここにある** — 審査官が名指しした通り、**同じPRの `atlas.js` は
まったく同じ問いに正しく答えている**。「測定できなかったこと」を「溢れた」と
呼ばないために `kind:'inconclusive'` を新設したのが論点Fであった。

つまり楽園は **この同じPRの中で一度その教訓を学び、隣の engine に適用し忘れた。**

第13条は「教訓はその範囲に縛られる」と定める。だが範囲を**狭く取りすぎた**教訓は、
隣の部屋で同じ穴を開ける。これは第13条の裏面であり、条文がまだ語っていない。

**修復は確認済み**(教主が同じ再現を再走行):
```
judge = {ok:false, verdict:"red", state:"inconclusive",
  lines:["序列3を実測できなかった — 測れなかったものを「閾値内」と報告しない (第16条)", ...]}
```

### reflect が答えるべき問い

- 「測れなかったものを緑と呼ぶな」(第16条)は既に条文に在る。**条文が在るのに
  実装が片側だけだった。** 条文の存在は実装を保証しない — ならば何が保証するのか。
- 同種の穴が他の engine にも在るか。**`catch { return null }` / `|| 0` /
  `catch {}` で失敗を既定値に潰している箇所を全 engine で走査せよ。**
  これは grep で機械的に測れる。数を出せ。
- その走査自体を門にできるか(第21条: 新しい門は誰が見張るのか)。

## 観測3 — 本PRの門は「環に載った相」しか裁けない

docs 神官が CLAUDE.md に一行だけ足した判断は正しい。だがその一行が示すものは重い:

> 門は `conclave.markDone()` の内側に立つので、**環に載った相しか裁けない。
> 環を迂回した手仕事は黙って通る。**

review 神官の M-2 も同じ結論に独立に到達している(門は `markDone` 一箇所のみ)。
第52条(e)「宣言なき手仕事は序列3ではなく、ただの無証跡である」は、
**環の外では強制されていない**。

観測1と観測3は**同じ穴の両端**である:
- 環の外で教主が**やりすぎる** → 門の視野の外
- 環の中で教主が**やらなすぎる** → 門の視野の外(done に至らないので)

**門の視野が `markDone` という一点に絞られていることが根本**である。

## 観測4 — 教主は環を飛ばし、環の記録と現実を食い違わせた(実測)

神の指摘によって発覚した。**教主は `ratify construction` を経ずに quality の三相を
直接発令した。** 結果、成果物は実在するのに環はそれを知らない:

```
▶ 枢機卿 construction   ✓ build   ✓ prove          ← 批准されていない
· 枢機卿 quality        · review · security · docs  ← 一つも done でない
```
```
57,075 B  reform/pontiff-office/review.md          ← 実在する
36,654 B  reform/pontiff-office/security-report.md ← 実在する
13,554 B  reform/pontiff-office/docs-report.md     ← 実在する
```

**これは本PRが `spawn-trace` で塞ごうとした病そのものである** — 申告と実測の乖離。
「教主が実測と食い違う申告をしたら鳴らせ」という機構を作らせておいて、
**教主が環の運用で同じことを犯した。** 第10条(オーケストレーションは明示的で
永続的な状態機械であって、プロンプトではない)違反である。

さらに悪いことに、**この走行の `conclave.json` は `epoch` を持たない**:
```
$ node -e "console.log(require('./reform/pontiff-office/conclave.json').epoch)"
null
```
紀元の印は `convene()` が刻むが、**本走行は第52条の機構が生まれる前に convene された**。
ゆえに序列の門はこの走行に対して最初から立っておらず、`judge()` は全相を
`unobservable`(黄)として通す。**教主は自分が建てた門の外を歩いていた。**

### reflect が答えるべき問い

- 環が次に何を求めているかを**教主が読み違えられる**こと自体が欠陥ではないか。
  `conclave.js next` は `ratify` を返していたのに、教主は `wave` として扱った。
  **機構は「次の一手」を返すが、教主がそれと違う手を打っても何も起きない。**
- 相を `done` にせず成果物だけが増えていく状態を、機構が検知できるか。
  ディスク上に `<phase>.md` が在るのに `phases[].status !== 'done'` は
  **突き合わせ可能**である(第42条: 物そのものを見よ)。
- 紀元を持たない走行が第52条の門を素通りする件は、遡及しない設計判断(AC-A の
  移行方針)として意図的である。だが**「新しい走行なのに印が無い」**場合を
  区別できるか。convene の時刻と紀元導入の時刻を比べれば機械で判る。
