## 🔍 「2件の gap」の正体は、門の設計欠陥だった

`critic.js review graph --self` は 2件の LESSON REGRESSION を出し続けていた。

```
🔴 lesson:browser-cleanup: 「目視検証でブラウザを開いたら必ず閉じる」not addressed
🔴 lesson:late-research-still-rules: 「遅れて届いた証拠にも同じ効力がある」not addressed
```

これを「直すべき欠陥」と読むのは誤りだった。**両方とも行いの掟であり、
コードに文字列として現れようがない。** critic は全教訓を同じ方式で裁いていた:

```js
return looseIncludes(hay, needle)      // ← コードに単語が現れるか
  ? { ok: true,  note: 'lesson satisfied' }
  : { ok: false, note: 'LESSON REGRESSION' };
```

### 実測で判明した、遥かに重い事実

```
$ node -e "教訓30件を機構/規範に分類"
機構: 12   規範: 18
```

**30件中18件が規範。だが赤かったのは2件だけ。**

つまり残り16件は「守られていた」のではなく、**偶然コードに単語が現れただけ**だった。
判定は機能しておらず、**偶然に依存していた**。
2件の不運な赤が本物の欠陥に見え、16件の幸運な緑が真の盲目を隠していた。

## 🔧 第28条 — 測れぬものも憶えねばならぬが、点数を付けてはならぬ

教訓に `kind` を持たせた（既存の `|applies:` と同じ流儀）:

| kind | 裁き方 |
|---|---|
| `mechanism` | 従来どおり成果物と照合（実装が現れるべきもの） |
| `conduct` | **提示のみ。点数を付けない**（行いの掟） |

**二つの誤りは等価である:**
- 永久に赤 → 読まれなくなる。**無視される門は、無い門より悪い**（第21条の教訓）
- 緑にして黙らせる → 教訓が消える

正しい扱いは**毎回の審査で立ち続ける義務として提示すること**。

```
✓ lesson:browser-cleanup: CONDUCT — 実行時に守るべき掟（コードでは検証できない）: …
✓ lesson:late-research-still-rules: CONDUCT — …
VERDICT: the critic found nothing. Proceed to judgment.
```

**未宣言は `mechanism` に倒れる** — 既存31件の裁き方を変えない（後方互換）。
