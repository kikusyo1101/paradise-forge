# 【ループ2】第28条 — 規範の教訓は grep で裁けない

### 🔍 「2件の gap」の正体は門の設計欠陥だった

critic は全教訓を「コードに単語が現れるか」で裁いていた。だが教訓には二種類ある。

```
実測: 教訓30件のうち 機構12 / 規範18
     赤かったのは2件だけ → 残り16件は偶然コードに語が現れただけ
```

**判定は機能しておらず、偶然に依存していた。**
2件の不運な赤が本物の欠陥に見え、16件の幸運な緑が真の盲目を隠していた。

### 🔧 `kind` を宣言させ、conduct は提示のみ

**二つの誤りは等価である:**
- 永久に赤 → 読まれなくなる。**無視される門は、無い門より悪い**（第21条）
- 緑にする → 教訓が消える

正しい扱いは**毎回の審査で立ち続ける義務として提示すること**。
未宣言は `mechanism` に倒れ、既存の裁き方を変えない。

`critic.js review graph --self` が**初めて exit 0** になった。

# 【ループ3】第29条 — 生成物は真実の写しであって真実ではない

### 🔍 執行官が REWORK を出した。それが最良の発見になった

ループ2をpushしたところ**CIが落ちた**。ローカルは172全緑なのに。
原因は私が同じ時間に書いた検査自身だった。

```
実測: clone直後 lessons.json は 31件
      CIが再生成すると          0件   ← 1682行が消える
```

`lessons.json` はKGから生成される。CIにKGは無く、裁定ジョブが冒頭で再生成する。
**リポジトリの写しと実行環境の写しは、別の物である。**

同じ性質の生成物が3つ git 追跡下にあり、どれも同じ危険を持つ:
(1) 環境で中身が違う (2) 並行PRで必ず衝突する (3) 中身を前提にした検査は生成元の無い環境で落ちる

### 🔧 主張すべきは generator の性質

```js
// ✗ 作者の機械でしか真でない
assert.ok(lessons.some(l => l.kind === 'mechanism'));

// ✓ KGの有無に依らず真
assert.ok(/kind:\s*kind\s*\|\|\s*'mechanism'/.test(lessonsJsSource));
```

**第19条（在庫でなく供給線を検めよ）を内側に向けた形である。**
