## 4. `CONSTITUTION.md` — 第62条は既存条と矛盾しない。重複もしない。

### 4-1. 第55条(台帳の冪等性)との関係 — **矛盾なし / 重複なし**

第55条は**台帳という器**の掟であり、第62条は**門という器**の掟である。
最も近いのは第55条 (i)「門を守る門を立てよ」だが、**問いが違う**:

| | 第55条 (i) | 第62条 |
|---|---|---|
| 守る対象 | **故障注入の道具**(注入器・走行器・仮倉・素材の生成器) | **門の作法そのもの**(単一プロセス / cache 破棄 / 住所の振替) |
| 問い | 「主張する装置は生きているか」 | 「**その作法は何を見えなくするか**」 |
| 実測の出所 | `injectGauge` の assert を外しても鳴らなかった | 並行性の層 114 門が一本も鳴らなかった |

**第55条 (i) は道具の失効を扱い、第62条は作法の盲点を扱う。**
道具が完璧に生きていても、**単一プロセスでしか撃たない作法は競合を永久に見ない** ——
これは (i) では言えない。**ゆえに重複ではない。**

**矛盾の検査**(一つずつ照合した):

- 第55条 (b)「予防と治癒を二重に敷く」 ↔ 第62条 (a) の門は**治癒が競合下で成立することを凍結する**。
  第55条が命じた構造を、第62条が門にした。**同じ向き。**
- 第55条 (e)「冪等化は fail-open に倒す」 ↔ requirements §2-4 がロック(α)を**却下した根拠がまさにこれ**。
  第62条は「TOCTOU が 100% 破れる」と測ったが、**ロックを命じていない。**
  命じていれば第55条 (e) と正面衝突していた。**衝突を避けた設計になっている。**
- 第55条 (h)「読めなかった行を 0 件と数えるな」 ↔ 第62条 (b)「現物が無い機では skip を名乗れ」。
  **どちらも第16条の系**であり、同じ向き。

`--raw` の一節が、この註釈に**網羅の契約**を負わせている。

註釈が exit の四値だけを説けば、**読者は `healable` を exit の別名と誤読する。**

### 5-3. 提案する文(そのまま貼れる)

