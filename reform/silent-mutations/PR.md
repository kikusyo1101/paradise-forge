## 4. 第62条の要旨と、verify 相の裁定

> **門の形が、門の盲点を決める。振る舞いだけを撃つ門は、己の作法が隠した層を永久に見ない。**

実測が条を生んだ: **60 変異中 14 件(23.3%)に 471 門が無音。**
無音は層に偏り、「門の書き方」が **40%** で最悪、「並行性」と「exit」は **0%** だった。
**腕の差ではない。門の書き方の差である。**

- **(a) 門を建てるとき、その門の形が何を見えなくするかを言え。** 作法はすべて盲点と対になっている。
- **(b) 不可侵を主張ではなく測定にせよ。** —— **verify 相が最低限の四つを明文化した**:
  ① 不在(ENOENT)と不能(EISDIR / EACCES / ELOOP)を**別の値で**名乗れ
  ② 「前」は**その門の直前**であって走行の開始ではない。一度「無い」と名乗った後に現れたら鳴れ
  ③ 汚した門を**名で**呼べ
  ④ 外部の正当な営み(追記)と門の汚染(書き換え)を、分けられるなら形で分けよ。分けられないならそう書け
  **緩い条文は最弱の実装を許し、実測でそのすべてが破れた**(A4 / A7 / A48 / A49)。
- **(c) 振る舞いの門が届かない層は、ソースを静的に読む門で補え。** 射程は名指しで狭く切り、
  **射程の外は次の走行の残債として名を持て。**

**第55条 (i)(門を守る門)とは重複しない** —— (i) は**道具の失効**を、第62条は**作法の盲点**を扱う。
第38条・第58条(c)(e) との照合は `docs.md` §4 に一条ずつ。**矛盾は無い。**

### 条の末文についての裁定 —— **(ii) 実体を条に合わせた**

review【重大 D】と docs 相が独立に摘発した:
条は「**三本とも壊して鳴ることを別の門が撃つ**」と名乗っていたが、
**外から撃つ門は番兵の一本しか無く**、残る二層(並行・静的)で**無音が二件出た**(L3 / R3)。

**verify 相の裁定: 弱かったのは掟ではなく実体である。**

1. 条を弱めれば**次の走行は弱い掟の上に建てる**。第62条(a) 自身が
   「言えない盲点は、まだ誰も落ちていない穴」と書いている —— 穴を認めて掟を下げるのは条の精神と逆である。
2. 外の門を建てる代が**実測で +73ms**(子プロセスを一本も起こさない純関数とソース読み)。**弱める理由が無い。**
3. 建てた結果、**L3 / R3 の二件が両方 CAUGHT に変わった**。条を弱めていたら今日も無音だった。

条の末文は**何が撃つかを門の名で列挙し**、「この三本は後から建てられた」という経緯と
「**掟が実体より大きく名乗れば、次の走行はその嘘を土台にする**」という教訓を残す形に書き直した。
`codex.js index --write` → `codex.js check` を走らせた(exit 0 / 62 条一致)。
