## 1. 更新したファイルと差分の要旨

### 1.1 `README.md` (+40 行)

**(a) engine 表に 1 行 — `README.md:279`**

`graph/pulse.js` と `graph/export-state.js` の間に `graph/fold.js` の行を挿した。
他の engine の行と同じ密度で書いた三点:

- **何をする器か** — 「いま撃とうとしている走行は、既に撃たれたか」に、
  **鍵**(入力の内容ハッシュ)と**領収書**(台帳の1行)だけで答える。
- **どの条に仕えるか** — 第48条・第58条(鍵の住処は一つ / 住所は `abode.pathFor` を通る)、
  第62条(`ledger-unreadable` は `no-receipt` と別の語)、第37条(台帳は1回の走行の中だけ)。
- **どう名乗るか** — `Executed E out of N (R reused, key=…)` / `bail=…`、
  CLI は `fold-key` / `fold-status`。
- 加えて **P-1 と P-2 を混ぜない**ことを明記した(台帳の畳み / プロセス内の写像)。
  混同は「Atlas の裁定が走行をまたいで写される」= 第37条違反に直結するため、
  表の一行でも落とせない区別である。

**数値は一切書いていない。** 「門が何本」「何秒縮んだ」は census と gauge が語る。

**(b) 新節 `### 畳み — 同じ入力の走行を二度撃たない` — `README.md:181-215`**

置き場所は「テスト」章の末尾、`--gate` の絞り込みの直後。**意図的である** ——
絞り込み(`--gate`)は**門を減らす**機構で、畳みは**門を減らさない**機構である。
隣り合わせに置いて、読み手が両者を取り違えないようにした。節が語るのは 5 点:

1. **なぜ畳むのか** — 一回の CI の中で、入力が一字も違わない同じ自己診断が
   繰り返し撃たれ、同じ成果物が繰り返し検められていた。
   「同じ答えを二度買うのは、測定ではなく出費である」。
2. **門は一本も減っていない** — 節の**最初の太字**に置いた。
   畳みを「門の間引き」と読まれることが、この改修の最大の誤読リスクである。
3. **名乗りの読み方** — `Executed E out of N (R reused, key=…)` / `bail=…`。
   `E + R = N` が常に閉じること。bail の語彙を 7 語全て列挙し、
   **語彙を閉じる理由**(開けば「畳む必要が無かった」と「畳む機構が壊れていた」が
   同じ文になる)を書いた。`ledger-unreadable` ≠ `no-receipt` を太字で分離。
4. **出口** — `--no-fold` / `PARADISE_NO_FOLD=1`、切った走行は `bail=disabled` を名乗る。
   「疑いを晴らす手段の無い最適化は、最適化ではなく信仰である」。
5. **台帳は 1 回の CI の中でだけ有効** — 持ち越せば「今日の門が昨日の緑を名乗る」。
   第37条の裏口であることを明示した。

## 2. 条を足したか否かと、その理由

### 足した — 第63条

> **同じ入力の走行を二度撃つな。ただし畳んだことを機械が名乗らない畳みは、測定の放棄である。**

節は (a)〜(f) の六つ:

| 節 | 命じること | なぜ条に要るか |
|---|---|---|
| (a) | 鍵は入力の**中身**から採る。**鍵の住処は一つ** | 二つ在れば鍵が二通りに割れる。`fold.js` を新 engine にした理由そのもの |
| (b) | 畳んだことを**毎回 stdout で名乗れ**。`E + R = N` が閉じること | 名乗らない畳みは「速くなった」と「壊れた」を区別させない |
| (c) | 畳まなかった理由は**閉じた語彙**で。「無い」と「読めない」は別の語 | 語彙を開けば `bail=whatever` が生まれる |
| (d) | 領収書の**有効範囲を宣言**し、超えて持ち越すな。`=global` は構造的に畳まない | 持ち越しは第37条の裏口。賢く判定せず、判定できないものは畳まない |
| (e) | **出口を常に開けておけ**。切ったことも名乗れ | 疑いを晴らせない最適化は信仰 |
| (f) | 畳みは**門を減らす免罪符ではない** | 間引いたならそれは畳みではなく削除 |

### なぜ既存の条で足りないと判断したか

足さない判断も正当であるから、**まず覆いを探した**。最も近い三条を当たった:

- **第55条(台帳は冪等でなければならない)** — 律しているのは**刻まれた後の帳**である。
  「同じ観測を二度刻むな」は言うが、**刻む前の走行を二度撃つな**とは言っていない。
  むしろ台帳の冪等性は、重複した実行を綺麗に畳んで見せることで**重複の存在を隠す**。
  第63条の柱書きにこの関係を明記した。
- **第37条(不在は通過ではない)** — 畳みが**破りうる条**であって、畳みを**律する条**ではない。
  第37条は「検証されなかったものは証明されていない」と言うが、
  「では領収書に基づく再利用は検証か」には答えない。(d) がその境界を引く。
- **第22条(数は数え直せる)** — (f) が第22条に**依存している**(門の総数は census が言う)が、
  第22条自身は走行の重複について何も言わない。

**判定: 三条のいずれも「同一入力の走行の重複」を覆っていない。**
覆っていない掟を既存条の解釈で埋めれば、次の走行はその拡大解釈を土台にする
(第57条: 修理は掟を広げてはならない)。ゆえに足した。

### 足したことで生じた残債(隠さない)

第63条は**いま門を持たない条ではない**が、条文が名指しする六つの節のうち、
門が直接凍らせているのは (a)(b)(c)(e) である —— これらは `tests/fold.test.js` と
`tests/paradise.test.js` の fold 節が prove 相で撃った。
(d) の「走行をまたがない」は台帳の生存期間の設計に依り、(f) は census が数える。
**「第63条は全節が門で守られている」とは書かない** —— 第62条の末尾が
「掟が実体より大きく名乗れば、次の走行はその嘘を土台にする」と警告した通りである。
節と門の対応を機械で突合する仕掛けは**次の走行の残債**として名を持つ。

## 4. `CLAUDE.md` への提案(実ファイルは触っていない)

### まず「そもそも足すべきか」を論じる(第39条)

第39条は `CLAUDE.md` を**最初の1画面**と定め、住むものを四つに限った ——
役割と言語 / どこを読むかの**地図** / 機械が強制していることの**出所への指し示し** /
**機械が強制できない判断則**。そして diet 門が予算 4,096 B を機械で見張っている。

畳みをこの四つに当てると:

| 候補 | 第39条の裁き |
|---|---|
| 畳みの仕組み(鍵・領収書・台帳) | ❌ **写経** — README の節と `fold.js` の冒頭が語る。1画面に要らない |
| bail の 7 語 | ❌ **写経** — 語彙は `fold.js` の `BAIL_CODES` が**凍結**している。散文に写せば二つ目の住所になる(第30条) |
| 「畳みは門を減らさない」 | ❌ 数の主張に近い。census と README が言う |
| **「`Executed … reused …` を見たら、それは走行が畳まれた印である」** | ⭕ 候補 — **消すとコードから回復できない誤りが起きるか?** |

最後の一つだけが検討に値する。理由: 教主が全走を撃って
`Executed 0 out of 1 runs (1 reused, key=…)` を見たとき、
**これを「走っていない = 測れていない」と誤読して赤を疑う**か、逆に
**畳まれた走行を「自分が測った」と主張する**(第37条違反)おそれがある。
前者は無駄な再走を生み、後者は偽の緑を生む。

ただし**反論も強い**:

- 名乗りの文面自体が `reused` と `key=` を含んでおり、**出力が自己説明的である**。
- 疑った者の逃げ道(`--no-fold`)は README の節が語り、`fold-status` が名乗る。
- 第39条の基準は「消すと**コードから回復できない**誤りが起きるか」。
  この誤読は `node graph/fold.js fold-status` 一発で解ける —— **回復できる。**
- 1画面には既に「4. 改善の主張は gauge の前後数値で」という近縁の判断則が居る。

### 結論: **足さなくてよい。** ただし足すなら一行

判断を神に委ねる形で、二案を提示する(**どちらも実ファイルには書いていない**)。

**案A(足さない / 推奨)** — 変更なし。畳みの名乗りは自己説明的であり、
誤読は `fold-status` で回復できる。1画面の予算は、回復不能な判断則のために取っておく。

**案B(足すなら、この一行だけ)** — 「機械が強制できない判断則」節の 4 の直後に挿す:

```markdown
5. **`(N reused, key=…)` は「畳まれた」の印** — 畳まれた走行を「自分が測った」と
   名乗るな (第63条)。疑ったら `--no-fold` で撃ち直す。
```

**案B を採るなら守るべきこと**(提案に付す条件):

- **一行で収めること**。bail の 7 語も台帳の仕組みも書かない(写経は掟を弱める / 第39条)。
- **既存の番号を動かさないこと** — 末尾に 5 として足す。
- **diet 門(census.dietChecks)の予算 4,096 B を超えないこと**を、
  書いた後に `node graph/census.js check` で確かめること。**数は手で見積もらない。**
- 足すのは**神の承認**の後である。この相では提案に留める。
