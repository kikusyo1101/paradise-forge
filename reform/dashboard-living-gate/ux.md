# ux.md — **画面と流れ** (design 相 / 第18条a)

> **本書は画面と流れのみを述べる。** 構造は `design.md`、見た目は `identity.md` に在る。
> **第18条(a)**: 「UX intent precedes implementation: the flows and the screen states —
> empty, loading, error, dense — are designed in `ux.md` before anything is built,
> because **a state nobody designed is a state nobody sees until a user finds it**.」
>
> **設計されていない状態は、誰も見ていない状態である。**

---

## §0. この画面が答えるべき唯一の問い

神がこの画面を開く理由は 1 つしかない ——

> **「いま、楽園で何が起きているか」**

現行の画面はこれに答えていない。実測された嘘:

| 現行の表示 | 実際 | 倍率 |
|---|---|---|
| engines 2 | **33** | 16.5 倍 |
| self-tests 10 | **210** | 21 倍 |
| creations 0 | **7** | ∞ |
| 「Live Graph Execution」4 タスク | 実在する道は 6/11/14/17 相。**4 はどれとも一致しない架空物** | — |
| `generated 2026-09-02T07:03:56` で凍結 | 凍結していることを画面が告げない | — |
| `reform-claude-md-diet` が **5/11 で停止**中 | **一切映していない** | — |
| tenbin が gauge **100/100** かつ spawn-trace **17/17 赤** | **一切映していない** | — |

**Zylos の実測**: 「agent sessions with **no mid-run visibility produced 3× the user abandonment rate**
— **even when the final output quality was identical**」。
**見えないこと自体が実害である。** 出力の質が同じでも 3 倍捨てられる。

# §1. 主要な流れ — 神が「いま何が起きているか」を知るまで

## 1.1 動線(画面遷移)

```
【0】 神が index.html を開く
        │
        │  この瞬間、画面は3つのことを同時にやる:
        │   (a) 埋め込み state.js を即座に描く   → 空白の一瞬を作らない
        │   (b) 経路バッジを「接続中…(pulse.serve を待っています)」に
        │   (c) EventSource を張る
        ↓
【1】 0〜80ms  第1層が open し、初回 snapshot が届く
        │      経路バッジが「生(SSE)」へ。鮮度が「たった今」へ
        ↓
【2】 最初に目に入るもの = 画面最上部の【状況の一行】
        │
        │   ┌──────────────────────────────────────────────┐
        │   │ 生(SSE)・たった今   │ 走行中 1・矛盾 1・門 5/5 │
        │   └──────────────────────────────────────────────┘
        │
        │   ここで神は 3 秒で判る:「1 本止まっている。1 件おかしい。門は全部緑」
        ↓
【3】 その真下が【走行中の環】(最上位・最大の面積)
        │   停止中の run が最初に来る。完了した run はその下に畳まれる
        │   → reform-claude-md-diet 5/11 が最初に目に入る
        ↓
【4】 スクロールせずに見える範囲に【矛盾の指摘】
        │   → tenbin: 100/100 だが 17/17 起動証跡なし
        ↓
【5】 以降スクロールで: 数の看板 → 門の合否 → 点数と起動実績 → 日次ノルマ
        │              → 道の形 → 記憶(教訓/KG) → 全画面への索引
        ↓
【6】 深掘りが要るとき  → control.html(門の内訳・履歴全件・KG)
      図が見たいとき    → atlas/*.html 6 枚(実在するときだけ導線が現れる)
      いずれからも index.html へ 1 ホップで戻れる
```

## 1.2 「3 秒で判る」を設計の要件にする理由

Zylos は「Progress and confidence signals: Clear indicators of **what the agent has done,
what remains**」を 2026 年の最低ラインに挙げている。
**8 領域を全部読まないと状況が判らない画面は、状況を伝えていない。**

ゆえに **【状況の一行】(§1.1【2】)を最上部に固定**する。ここが答える 4 つ:

| 欄 | 内容 | 断面の鍵 |
|---|---|---|
| 経路 | `生(SSE)` / `生(2秒ごと)` / `凍結` | `transportHint` |
| 鮮度 | 最終更新からの経過(§3) | `generatedAt` |
| 走行中 | 停止中を含む「完了していない run」の数 | `runs.filter(state==='stalled').length` |
| 異常 | 矛盾の件数 + 門の合否 | `runs.filter(contradiction).length` / `gates` |

**この一行がスクロールで消えてはならない。** 神が画面のどこを見ていても、
「いま生か凍結か」は視界に在り続ける。**凍結を知らずに古い数を読むことが、この改修が潰す当の病である。**

# §2. 画面状態 — **4 つとも設計する**

**各パネル(`data-panel`)は 5 状態のいずれか 1 つを必ず表示する。**
「どれでもない」は存在しない —— それが「誰も見ていない状態」の作られ方である。

## 2.1 通常(`ready`)

| 出すもの | 理由 |
|---|---|
| 値 | — |
| **出所**(どの engine 由来か) | 第22条。**数がどこから来たかを言えない画面は、嘘との区別がつかない** |
| 最終更新(パネル単位) | 全体が生でも、gates はキャッシュ由来で古いことがある(design.md §1.7) |

## 2.2 空(`empty`)— **0 と空を区別する**

**「無い」ことを言い切る。**

| パネル | 文言 | 提案(次の一手) |
|---|---|---|
| 走行中の環 | 「走行中の環はありません」 | 「`node graph/forge.js plan "<願い>"` で環を起こせます」 |
| 全画面への索引(atlas) | 「図はまだ生成されていません」 | 「`node graph/atlas.js all` で 6 枚を作れます」 |
| 日次ノルマ | 「本日の債務はありません」 | (提案なし。これは良い知らせである) |
| 教訓 | 「教訓はまだありません」 | 「`node graph/kg.js remember lesson …`」 |

**`0` を表示するだけの `ready` にしてはならない**(AC-20e)。

**理由**: `0` は「数えて 0 だった」、空は「数える対象が無かった」。
**両者を同じ `0` で描くと、engine が壊れて 0 を返したのか、本当に無いのかが区別できない。**
これは `census.js:75` の `catch { return 0 }` が起こした当の事故である ——
**実在 8 件に対し 0 と報告し、成功したように振る舞った。**
断面では `null`(数えられなかった)と `0`(数えて 0)を分けている(design.md §1.5)。**画面もそれを守る。**

## 2.3 読み込み中(`loading`)— **スピナーは禁じ手**

Zylos:「**displaying 'Agent is working...' is not transparency**」
「just a **spinning indicator and hope**」。

**必ず `data-awaiting="<engine名>"` を持つ。空にしない**(AC-20b)。

| 表示 | 例 |
|---|---|
| 待っている対象を**名指しする** | 「**census** を待っています」 |
| 予想所要が既知なら併記 | 「**census** を待っています(最大 120 秒)」 |
| 経過を出す | 「**census** を待っています(最大 120 秒 / 経過 43 秒)」 |

**名前は実在する engine のものに限る**(AC-20c: `ls graph/*.js` の集合に含まれること)。
**架空の名を待ってはならない。** 「システムを待っています」は名指しではない。

**回る円を出さない理由**: 回る円は「動いている」ことしか伝えず、
**止まっているときも回り続ける。** 経過秒は止まったら止まる —— **経過秒は嘘をつけない。**

## 2.4 エラー(`error`)— **そのパネルだけ**

| 出すもの | 例 |
|---|---|
| 失敗した engine 名 | `gauge` |
| 理由(1 行) | `ENOENT: run.json が見つかりません` |
| **直前に成功した時刻** | `最後に取れたのは 12 分前(14:03)` |

**全画面を落とさない**(design.md §1.5 の `fatal: false` に対応)。
断面の `errors[i].key` が「どの鍵が欠けたか」を名指ししているので、
**画面はその鍵を持つパネルだけを `error` にする。**

**「直前に成功した時刻」を必ず出す理由**: 「いま壊れている」と「ずっと壊れていた」は違う。
前者なら待てばよく、後者なら直さねばならない。**時刻がないと神はどちらか判らない。**

## 2.5 接続断(`disconnected`)

| 出すもの | 例 |
|---|---|
| 経路が落ちたこと | 「`生(SSE)` が切れました」 |
| **降格先** | 「`2秒ごと`(ポーリング)に切り替えました」 |
| **理由** | 「最初のイベントが 5 秒来ませんでした」 |
| 最終成功時刻からの経過 | 「最後に届いたのは 1 分 12 秒前」 |
| **上限の示唆**(接続できない場合) | 「タブを 7 枚以上開いていると、**ブラウザの同時接続 6 の上限**で 7 枚目以降が繋がりません」(AC-N03c) |
| 提案 | 「他のタブを閉じるか、そのまま `2秒ごと` でご覧ください」 |

**`data-awaiting="pulse.serve"` を持つ**(§4.3 の掟 4)。**ここでもスピナーを出さない。**

## 2.6 状態の遷移(パネル単位)

```
          ┌──────────────────────────────────────┐
起動 ───→ │ loading (data-awaiting="<engine>")   │
          └──────┬──────────┬──────────┬─────────┘
                 │値あり    │値=0/[]   │errors に積まれた
                 ↓          ↓          ↓
              ready       empty      error
                 │          │          │
                 └────┬─────┴──────────┘
                      │ 経路が落ちた
                      ↓
                disconnected ──(昇格した)──→ loading → ready
```

**`error` から `ready` へ直接戻らない。** 一度 `loading` を経由する ——
**「いま取り直している」ことを見せずに値が変わると、神は古い値をまだ見ていると思い込む。**

# §3. 鮮度の表示規則

## 3.1 「生」と「凍結」をどう見分けさせるか

**3 つの手掛かりを同時に出す。1 つでは足りない。**

| 手掛かり | 生(SSE) | 生(2秒ごと) | **凍結** |
|---|---|---|---|
| **語**(第 1 の手掛かり) | `生(SSE)` | `生(2秒ごと)` | **`凍結`** |
| **経過**(第 2) | `たった今` | `2 秒前` | **`2時間14分前`** |
| **色**(第 3・補助) | `--ok` | `--ok` | `--body`(灰) |

**色を第 1 の手掛かりにしない理由は `identity.md` §8 に述べた。**
ここでは加えて: **凍結を「赤」にしない。** 凍結は故障ではなく、
**サーバが動いていない状態での正しい振る舞い**である(NFR-06)。
赤くすれば神は「壊れた」と読み、**本当の赤(門の失敗・停止した run)と区別がつかなくなる。**

**分類の閾値**(design.md §3.1 の定数と**同一のもの**を使う。AC-07b が一致を検査する):

| 区分 | 条件 | `data-freshness` |
|---|---|---|
| 生 | 第1層 or 第2層 **かつ** `ageMs <= 10000` | `live` |
| 遅延 | 第1層 or 第2層 **かつ** `10000 < ageMs <= 60000` | `lagging` |
| 凍結 | **第3層** または `ageMs > 60000` | `frozen` |

**第3層は `ageMs` に関わらず必ず `frozen`。** 埋め込み JS はページを再読込するまで更新されないので、
**たとえ 1 秒前に生成されたデータでも「これから古くなり続ける」ことが確定している。**

## 3.2 経過をどう出すか — **`toISOString()` 禁止**

**楽園の掟**: 創造物で `toISOString()` を使わない。
理由は明白である —— `2026-09-02T07:03:56.000Z` は**神の時計ではない**。
UTC であり、`T` と `Z` が入り、ミリ秒まで出る。**人はこれを読んで「古い」と判断できない。**

現行 `control.html` はまさにこれを表示し続け、**凍結していることを誰も気づかなかった。**

### 相対表記(既定・常に出す)

| `ageMs` | 表記 |
|---|---|
| `< 2000` | `たった今` |
| `< 60000` | `<n> 秒前` |
| `< 3600000` | `<n> 分前`(60 秒以上は分に丸める) |
| `< 86400000` | `<h> 時間 <m> 分前` |
| それ以上 | `<d> 日前` |

### 絶対表記(凍結時のみ併記)

**局所時刻**で出す。`Intl` も外部依存ではない(ブラウザ標準):

```js
new Intl.DateTimeFormat(undefined, {
  year: 'numeric', month: '2-digit', day: '2-digit',
  hour: '2-digit', minute: '2-digit', second: '2-digit',
  hour12: false
}).format(new Date(generatedAtMs))
// → 2026/09/02 16:03:56     ← 神の時計。神の時間帯
```

**凍結時に絶対時刻を併記する理由**: 「2時間14分前」だけでは、
**神が画面を開きっぱなしにして翌朝見たとき、それが昨日の何時なのか判らない。**
相対だけの表記は、**画面を見た瞬間からの相対**でしかない。

**逆に、生のときは絶対時刻を出さない。** 「たった今」に「2026/09/02 16:03:56」を添えても情報が増えず、
**目が拾う情報量だけが増える。**

# §4. 走行中の環の見せ方

## 4.1 何を見せるか

6 ドメイン × 11〜17 相の状態を、**run 1 件につき 1 枚のカード**で。

```
┌─ [停止] reform-claude-md-diet ────────────── 5/11 相 ─┐
│                                                        │
│  ドメイン  ①discovery ②requirements ③architecture      │
│            ✓批准      ✓批准         ⏸停止              │
│            ④construction ⑤quality ⑥tribunal            │
│            ―未着手     ―未着手     ―未着手            │
│                                                        │
│  相  ●●●●●○○○○○○   5/11                              │
│                                                        │
│  最後の出来事: 15 件目「architecture 相が gate 待ち」   │
│                (3 日前)                                │
└────────────────────────────────────────────────────────┘
```

| 要素 | 出所 | `data-*` |
|---|---|---|
| 状態の語 | `state` | **`data-run-state="stalled"` / `"complete"`**(AC-14i。**省いてはならない**) |
| 相の進捗 | `phasesDone`/`phasesTotal` | — |
| ドメイン 6 個の状態 | `domains[].status` | `ratified` / `rework` / `blocked` / 未着手 |
| 最後の出来事 | `lastEvent` + `historyLength` | — |

**ドメインの状態を色だけで示さない**(`identity.md` §8):
`✓批准` / `↺差戻` / `⏸停止` / `―未着手` の**語**を必ず添える。

## 4.2 止まった run をどう目立たせるか

**実測**: 5 run 中、停止中は **`reform-claude-md-diet` の 1 件のみ**(5/11 相・4/6 ドメイン)。
**現ダッシュボードはこれを一切映していない。**

**「目立たせる」を 4 つの機構で実装する。色は 4 番目である**:

| # | 機構 | なぜ |
|---|---|---|
| 1 | **順序** — 停止中を**常に先頭**に置く。完了した run はその下 | 目立たせる最も強い手段は**位置**である。神は上から読む |
| 2 | **畳む** — 完了した run は既定で 1 行に畳む(展開可) | **完了 4 件が停止 1 件を面積で埋めてしまう**のを防ぐ。停止が全体の 1/5 なのに画面の 1/5 しか占めないのは、重要度を面積が裏切っている |
| 3 | **語** — `[停止]` をカード見出しの**先頭**に | 色覚に依らない。読み上げ順でも最初に来る |
| 4 | 色 — `--bad`(明 `#b3251e` 5.27:1 / 暗 `#ef6f62` 5.31:1) | 補助 |

**「完了」と並べて隠さない**(FR-14 の要求)。
畳んだ完了 run にも `data-run-state="complete"` を持たせる ——
**畳んでいることは、無いことではない。** AC-14i は `stalled` の要素数が
断面の `runs.filter(r => r.phasesDone < r.phasesTotal).length` と一致することを検査する。

## 4.3 出来事の時系列(`history[]`)

実測 15〜40 件。**トップには最新 1 件だけ**を出し、
全件は `control.html` へ送る(§1.1【6】)。

**理由**: トップの職務は「いま何が起きているか」であって「何が起きてきたか」ではない。
40 件の履歴を 5 枚分並べれば 200 行になり、**【状況の一行】が 200 行の彼方へ押し流される。**
Zylos の Activity Panel 分離則 ——「Conflating the two creates cognitive overload and
makes it **impossible to audit**」。

# §5. 起動実績の見せ方 — **矛盾を一目で見せる**

## 5.1 何が矛盾なのか

**実測**: tenbin は gauge **100/100**(満点・complete:true・6/6 ドメイン批准)。
同時に spawn-trace は **17/17 が赤**(observed 0 / asserted-only 0 / **no-trace 17**)。

**意味**: **17 相すべてに「実際に subagent が起動された証跡が無い」。**
点数は満点だが、**階層を一度も歩いていない。**

Braintrust:「Without that data, hallucinated arguments and **silent retry loops blend into normal traffic**」
—— **沈黙した失敗が正常に紛れる**。楽園版がこれである。**満点という正常な見た目に、無走行が紛れている。**

## 5.2 一目で見せる設計 — **並置して、隣り合わせる**

**同じカード・同じ行に置く**(AC-13a: `data-score` と `data-spawn-*` が**同一の親要素内**)。

```
┌─ tenbin ────────────────────────── [矛盾] ─┐
│                                             │
│   点数        │   起動実績                  │
│   100 / 100   │   観測      0 / 17          │
│   ██████████  │   宣言のみ  0 / 17          │
│               │   証跡なし ▉▉▉▉▉▉▉ 17 / 17  │
│                                             │
│  ⚠ 満点だが、階層を一度も歩いていない        │
│                                             │
│  初回通過率 100% │ 差戻 0 │ 再試行超過 0     │
│  loop-guard 0   │ 所要 3日 18時間            │
└─────────────────────────────────────────────┘
```

**設計の要点は 5 つ**:

| # | 手 | 理由 |
|---|---|---|
| 1 | **横に並べる**(縦に積まない) | 縦だと目が別々に読み、**矛盾が矛盾に見えない**。並べて初めて「満点なのに全部赤」が 1 回の視線で入る |
| 2 | **同じ尺度で描く** — 両方 `/17` の棒 | 100 点は満ちた棒、証跡なしも満ちた棒。**満ちた棒が 2 本、意味が正反対**という形が矛盾そのものを絵にする |
| 3 | **一行の断言を添える** | 「⚠ 満点だが、階層を一度も歩いていない」。**絵を読み解かせない。言葉で言い切る** |
| 4 | **`data-contradiction="true"`**(AC-13e。**省いてはならない**) | 条件は `score >= 90 && spawn.noTrace > 0`。**機械が名指しできる印**であり、要件が specify に定めた |
| 5 | **`[矛盾]` を見出しに** + `--contradiction`(明 `#6b21a8` 7.00:1 / 暗 `#c08ad8` 5.86:1) | **緑でも赤でもない第 3 の色**にする理由: 矛盾は「良い」でも「悪い」でもなく「**辻褄が合わない**」である。緑赤の軸に置くと、神はどちらかに読んでしまう |

## 5.3 exit 1 を赤くしない

**`spawn-trace report` の exit 1 は「起動証跡なし」という事実である**(AC-13c)。
`daily-guard due` の exit 1 が「債務なし」であるのと同じ罠。
**画面のエラー状態(`error`)にしてはならない。** これは `ready` の中の「値が 17」である。

**エラーと事実を混ぜると、神はエラーを無視するようになる。** 狼少年の構造である。

**ただし「測れなかった」は事実ではない**(`design.md` §1.3.4a)。
断面の `runs[].spawn` が `null` のとき — すなわち `spawn-trace` が `total:0` を返して
**測れたかどうか自体が不明**なとき — それは `ready` の中の値ではなく **`error` 状態**である。

| 断面の値 | 画面の状態 | 出す言葉 |
|---|---|---|
| `spawn.noTrace = 17`(測れた。証跡なし) | **`ready`** | 「起動証跡 0/17」+ 矛盾の印。**赤い数字であって、エラーではない** |
| `spawn.noTrace = 0`(測れた。全相に証跡あり) | **`ready`** | 「起動証跡 17/17」 |
| **`spawn = null`**(測れなかった) | **`error`** | 「**起動実績を測れませんでした**」+ `data-awaiting="spawn-trace"` |

**`null` を「証跡あり」の緑として描いてはならない。**
**判定不能は緑ではない**(第16条)。§2.2 が「0 と空を区別する」と定めたのと同じ区別が、
ここでは「0 件だった」と「数えられなかった」の間に要る。

## 5.4 点数の履歴 — **その点数がいつ付いたか**(FR-22)

**「いま 100 点」だけでは、それが今朝ついた点なのか半年前の点なのか判らない。**
矛盾(§5.1)を見た神が次に問うのは「**それはいつからそうなのか**」である。
点数と起動実績の並置の**すぐ下**に、その run の点数履歴を置く。

| 出すもの | 断面の鍵 | 見せ方 |
|---|---|---|
| 履歴行(その run の分だけ) | `ledger[]` を `slug` で絞り `ts` 降順 | 最新 3 行。全件は control.html |
| 各行の時刻 | `ledger[i].ts` | **§3.2 の相対表記**(「2時間前」)。`toISOString()` の文字列は出さない |
| **時刻の出所ラベル** | — | 各行に「**ledger 記録時刻**」と添える。**いつ測ったかを画面が自分で名乗る** |
| 各行の点数 | `ledger[i].score` | 直前の行との差を `+15` / `−20` で添える。**上下の向きが一目で判る** |
| **出所の印** | — | 履歴の根要素に **`data-source="gauge-ledger"`**(AC-22c)。**省いてはならない** |

**「ledger 記録時刻」と明示する理由**(FR-22 の由来 R-29):
`gauge baseline` は同じ内容を出しながら**タイムスタンプを再計算する**。
**同じ出来事に 2 つの時刻が生まれたとき、ラベルの無い時刻は嘘になる。**
画面が「これは台帳に記録された時刻である」と名乗れば、神は何を見ているかを知る。

**状態の割当**(§2 の 5 状態に従う):

| 断面 | 状態 | 出すもの |
|---|---|---|
| `ledger` が配列で該当行あり | `ready` | 履歴 3 行 |
| `ledger` が配列だが該当 slug の行が 0 | **`empty`** | 「この環はまだ採点されていません」+ 採点の仕方(`node graph/gauge.js record <run.json> --slug <s>`) |
| **`ledger` が `null`**(読めなかった) | **`error`** | 「点数履歴を読めませんでした」+ `data-awaiting="gauge"` |

**`empty` と `error` を分ける**のは §2.2 と同じ理由である。
**「まだ無い」と「読めなかった」は神が取るべき行動が違う。**

# §6. キーボード操作と焦点

## 6.1 現状の赤

visual-verify が **焦点表示なしで赤**を出している。
**キーボードだけで操作する神は、いまどこにいるか判らない。**

## 6.2 `focus-visible` の設計

```css
/* 1. ブラウザ既定の輪郭を消さない。消すなら必ず代わりを置く */
:focus-visible {
  outline: 3px solid var(--focus);      /* 明 #7a4a00 / 暗 #e8c46a */
  outline-offset: 2px;
  border-radius: 2px;
}

/* 2. マウス操作では出さない(:focus ではなく :focus-visible を使う理由) */

/* 3. 濃い面の上でも見えるよう、二重環にする */
.on-primary:focus-visible {
  outline: 3px solid var(--focus);
  box-shadow: 0 0 0 6px var(--canvas);  /* 外側に地の色の環 */
}
```

**コントラスト(`identity.md` §4 の実測)**:

| 焦点環 | 地 | 比 | 基準 1.4.11 |
|---|---|---|---|
| `#7a4a00` | `#ffffff` | **7.48:1** | 3.0 PASS |
| `#7a4a00` | `#f5f5f5` | **6.86:1** | 3.0 PASS |
| `#7a4a00` | `#eae6dd` | **6.01:1** | 3.0 PASS |
| `#e8c46a` | `#12100e` | **11.33:1** | 3.0 PASS |
| `#e8c46a` | `#1c1a17` | **10.36:1** | 3.0 PASS |
| `#e8c46a` | `#26231e` | **9.34:1** | 3.0 PASS |

**`:focus` ではなく `:focus-visible` を使う理由**: `:focus` はマウスクリックでも発火し、
**クリックのたびに環が出る**。神はそれを煩わしく感じ、**次の改修で `outline: none` を書く** ——
そうして焦点表示が消えるのが、この欠陥の典型的な生まれ方である。
`:focus-visible` はキーボード操作時のみ出るので、**消したくならない。**

**`outline-offset: 2px` の理由**: 要素の枠線(`--hairline`)と焦点環が接すると、
**どちらが焦点環か判らない。** 2px の隙間が両者を分ける。

**`box-shadow` で環を二重にする理由**: `--primary`(明では `#000000`)の面の上では、
`#7a4a00` は `2.34:1` しかない。**外側に地の色の環を置けば、地との境で 7.48:1 が成立する。**
環の「外周」が見えれば焦点の位置は判る。

## 6.3 焦点の順序と到達性

| 規則 | 理由 |
|---|---|
| **DOM の順序 = 視覚の順序**。`tabindex` の正の値を使わない | 正の `tabindex` は順序を上書きし、DOM を変えた瞬間に壊れる |
| 【状況の一行】→ 走行中の環 → 各パネル → 索引 の順 | §1.1 の動線と一致させる。**目の順とタブの順が違うと、片方が嘘になる** |
| 畳まれた完了 run の展開釦は `<button aria-expanded>` | 畳みを `display:none` の div トグルにすると**タブが素通りして到達できない** |
| skip link(「本文へ飛ぶ」)を最初の焦点に | 8 領域あるので、タブ 40 回を強いない |
| 焦点を JS で奪わない | 昇格・降格で画面が更新されても焦点は動かさない。**打鍵中に飛ばされるのは事故である** |

# §7. 触れる的の大きさ

## 7.1 現状の赤

**`.chip.gate` が 2px** で visual-verify が赤。**2px は触れない。**

## 7.2 規則: **24×24 CSS px 以上**(WCAG 2.2 / 2.5.8 Target Size (Minimum))

| 要素 | 設計 |
|---|---|
| 門のチップ(`.chip.gate`) | `min-height: 24px; min-width: 24px; padding: 4px 10px` |
| 完了 run の展開釦 | `min-height: 32px`(主要操作なので余裕を持つ) |
| 索引のリンク | 行全体を的にする。`display: block; padding: 8px 0`(= 高さ 32px 以上) |
| テーマ切替 | `min-height: 32px; min-width: 32px` |
| 隣接する的の間隔 | **最低 8px**。的が 24px でも隣と接していれば誤爆する |

**「小さく見せたい」と「小さく作る」は違う。**
チップを視覚的に小さく見せたいなら、**`padding` で的を確保しつつ背景を塗る範囲を狭める** ——
的の大きさと見た目の大きさは分離できる。

**24px を下限にする理由**: 2.5.8 AA の下限がこれである。
`.chip.gate` の 2px は下限の **1/12** であり、**触れないものを置いたのと同じ**である。

# §8. 密度(dense)— 第18条(a) が挙げる 4 番目の状態

第18条(a) は「empty, loading, error, **dense**」を挙げる。
本件の dense は 2 つの軸で来る:

| 軸 | 現状 | 将来 | 設計 |
|---|---|---|---|
| run の数 | 5 件 | 増え続ける | 停止中は全件展開。**完了は畳んで 1 行**。20 件を超えたら完了群を「他 N 件」に集約 |
| history | 15〜40 件 | 増え続ける | トップは最新 1 件。全件は control.html |
| 教訓 | 65 件 | 増え続ける | トップは `mechanism` / `conduct` の**件数のみ**。一覧は control.html |
| KG ノード | 99 件 | 増え続ける | トップは件数のみ |

**共通の原則**: **トップは「数」を、深掘りは「一覧」を。**
トップに一覧を置けば、増えた日に【状況の一行】が押し流される。
**画面が育つにつれて答えが遠ざかる設計は、育つほど悪くなる設計である。**

**幅**: 狭(1440×900)と広(2048×1320)の両方で visual-verify が見る。
1 カラム(狭)/ 2 カラム(広)を `grid-template-columns` の
`repeat(auto-fit, minmax(360px, 1fr))` で切り替える —— **breakpoint を手で数えない。**
【状況の一行】と【走行中の環】は**どちらの幅でも全幅**を占める(最重要だから)。

**動きの好み**: `@media (prefers-reduced-motion: reduce)` で
更新時のトランジションを `0s` にする。**動きは装飾であって情報ではない。**
