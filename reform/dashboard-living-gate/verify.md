## 教主が三度目に測り方を誤った記録

第1版は「止まった環 = 0件」と出した。だが**門ではなく教主が誤っていた**。

```
私が読んだ鍵:   r.stalled          ← 存在しない
実際の鍵:       r.state === 'stalled'
```

断面の鍵は `name, path, phasesDone, phasesTotal, domainsRatified, domainsTotal,
domains, state, score, spawn, contradiction, metrics, historyLength, lastEvent,
scaleGuess, scaleCandidates` である。**推測で鍵名を書いた。**

### 則D(再確認)は測る側にも向く

prove 相で立てた則D — **「壊れたことを先に証明せよ。門を疑うのはその後である」** —
は、故障注入だけの話ではなかった。

**測って赤が出たとき、答えは二つある:**
1. 実装が満たしていない
2. **測り方が的を外している**

この改修で教主は三度、2 に嵌った:

| # | 場面 | 誤り |
|---|---|---|
| 1 | prove: G-01 | `articles:` を出所の行(:476)で置換。数を作る :368 ではなかった |
| 2 | prove: 第30条 | 門は `path.join` を見るのに `require('path').join` と書いた |
| 3 | verify: (e) | 断面の鍵を `stalled` と推測。実際は `state === 'stalled'` |

いずれも**実装は正しく、教主が間違っていた**。
第9条「楽園は裁かれる前に自らを疑う」は、裁く側にも等しく向く。

## 測定条件の汚染について(第21条の応用)

verify の途中、自己診断が 278/0 → 276/2 → 277/1 → 276/2 と揺れた。
原因を数で確定させた:

```
$ tasklist | grep -c chrome.exe                      → 28
$ ls $TEMP | grep -c archify-visual-check-profile    → 87
$ ls -d $TEMP/paradise-test-atlas*                   → **2**   ← 決定的
```

**`paradise-test-atlas` が2つある。** これは自己診断の第21条テストが使う作業場の名である。
つまり**自己診断が使う作業場に、神官が同時に入っていた。**

失敗の中身も一致する:
```
Error: navigation failed: net::ERR_FILE_NOT_FOUND
  ✗ atlas: 全ての道が図になる (第47条)
  ✗ atlas: 門は己の残骸で落ちない — 同じ作業場で二度走る (第21条)
```

第21条の試験は「同じ作業場で**二度**走る」ことを検める。
だが実際には**三人が同時に走っていた**。一方が書いた HTML を他方が消す。

### ゆえに立てた則E

**並行作業中の測定値を、単独走行の値と比べてはならない。**

同じ症状(`ERR_FILE_NOT_FOUND`)が、この改修で二度現れた:

| 時期 | 症状 | **原因** |
|---|---|---|
| 監査時 | ERR_FILE_NOT_FOUND | 己の残骸(Chrome プロファイル漏れ 483→683) |
| verify 時 | ERR_FILE_NOT_FOUND | **隣人の作業**(神官3人が同じ作業場を共有) |

**症状が同じでも原因が違う。** 一度目の経験から「また漏れた」と決めつければ、
根治済みの修理を疑って時間を溶かす。逆に「前に直したから汚染だろう」と
決めつければ、本当の再発を見逃す。

**どちらでもなく、測る。** 走っているプロセスの数を数え、作業場の数を数える。
それだけが両者を分ける。

ゆえに: 土台の緑は、**神官が全員退いてから単独で測り直す。**

## 単独走行での再測 — F-1 への回答

神官が走らせた2回は **277/1** と **276/2** であった。

だが原因は実装の欠陥ではなく、**測定条件**だった。神官が全員退いた後、

**基点は再現した。**

### だが F-1 を「汚染だから無視してよい」とはしない

神官の指摘には**正しい核**がある:

> `findings-flaky-gates.md` の形#3 は「(調査中)」のまま未解決

これは教主の記録漏れだった。形#3(`failAll` の unhandled rejection)は
**停止前に根治済み**であり、その旨を追記した。神官が読んだ時点では
「調査中」と書かれたままで、**文書が実態より古かった**。

**第29条の逆の形である**: 生成物ではなく散文が、実態から遅れて腐っていた。
神官は文書を正しく読み、文書が嘘をついていた。

### ゆえに則Eに補足する

**則E: 並行作業中の測定値を、単独走行の値と比べてはならない。**
**補足: だが「汚染だった」で終わらせるな。** 汚染下でも神官は
`findings-flaky-gates.md` の記述漏れという**真の欠陥**を見つけていた。
条件を疑うことと、指摘の核を受け取ることは両立する。
