## E. 前任の作法の問題(繰り返さないために)

### E-1. `git add -A` で他人の変更を巻き込んだ

```
$ git log -S "MAX_PHASE_RESUME = Infinity" --oneline
ea72f09 quality(reform): 自己診断 288/288 緑 — README を実数へ   ← 教主のコミット
```

隣人の作業ツリー変更(第51条c違反)を**自分のコミットに固定した**。
自己診断が咎めるまで気づかなかった。

**→ 則G: `git add -A` を使うならコミット前に `git diff --cached` を読め。**

### E-2. 共有された作業場での作業を、最後まで構造的に分離しなかった

worktree を使ったのは**四度目の干渉の後**である。
一度目(`MAX_PHASE_RESUME` の書換)の時点で分離していれば、
E-1 も起きなかった。

**→ 隣人が同じリポジトリに居ると分かった時点で worktree を切れ。**

### E-3. 測定と作業を並行させた

判定材料の作成・atlas 生成・自己診断を同時に走らせ、
`ERR_FILE_NOT_FOUND` を3回踏んだ。毎回「汚染か真の欠陥か」を
切り分ける時間を溶かした。

**→ 則E: Chrome を使う検査は単独で走らせる。**
