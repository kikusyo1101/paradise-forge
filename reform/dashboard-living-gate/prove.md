# prove 相 — 教主自身の手で門を壊した記録

> 神官は故障注入11件を実証したと報告した。**第27条により、教主は主張ではなく実物で確かめる。**
> 壊す → 赤を見る → 戻す → 緑を見る。それだけが「門が生きている」ことの証明である。

## 教主が二度、自分の壊し方を誤った記録

第1版の実行では2件が「鳴らない」と出た。だが**門ではなく教主が誤っていた**。

### 誤り1: 数を作っていない行を書き換えた

```
私が壊した箇所:  graph/pulse.js:476  articles: 'codex', engines: 'pulse', ...
                                     ↑ これは**出所を記す行**
本当の急所:      graph/pulse.js:368  counts.articles = guard(errors, 'codex', ...)
```

`articles:` という文字列は当たったが、そこは数を作っていない。
**壊したつもりで壊せていなかった。**

### 誤り2: 門が見ている形と違う形で書いた

```
門が見る正規表現: /path\.(join|resolve)\s*\([^)]*['"`]creations['"`]/
私が書いた行:     const _bad = require('path').join(ROOT, 'creations');
                              ↑ `require('path').join` は `path.join` に一致しない
```

## ゆえに立てた則

### 則D: **壊れたことを先に証明せよ。門を疑うのはその後である**

故障注入で門が鳴らないとき、答えは二つある:

1. 門が壊れている(見ていない門)
2. **注入が的を外していて、そもそも壊れていない**

**2 を先に潰さなければ、健全な門を「鳴らない」と誤断罪する。**
これは第16条(判定不能は緑ではない)の裏返しで、**判定不能を赤と決めつけてもいけない**。

実装上は、置換の前後で文字列が変わったかを確かめるだけでよい:

```js
const mutated = mutate(src);
if (mutated === src) {
  // 門の責任ではない。教主の壊し方の誤りである
}
```

第2版ではこれを組み込み、G-04 について「置換が当たっていない」と正しく自己申告できた。

## この記録の意味

第23条(b)は「gate が健全な系しか見たことがないなら、それは試されていない」と述べる。
だが**試す側が的を外していれば、試したことにならない**。

門を壊す作業そのものにも、門が要る。
