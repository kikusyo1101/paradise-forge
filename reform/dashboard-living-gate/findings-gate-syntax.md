# 門の書き方そのものが門を素通りしていた — 5件の実測

> discovery 枢機卿の審査(4件)と、差戻し後の神官の自己走査(1件)で見つかった欠陥。
> **すべて教主が独立に再現した。** 主張ではなく実出力である。

## 共通する病

要件書は全ての門(G-01〜G-10)に「**壊すと赤くなること**」を課した。
だが **AC を書いた文字列そのものが、壊れていても赤くならない**形をしていた。

**第50条の三重目の形である**:

| 形 | 内容 | 出典 |
|---|---|---|
| 表 | 門が**見ていない**機能は、壊れても鳴らない | 第50条 |
| 裏 | 門が**己の残骸**で不定に鳴る | findings-base-red.md |
| **三** | **門の書き方が誤っていて、壊れていても鳴らない** | 本文書 |

三つ目が最も危険である。前二者は「鳴らない/誤って鳴る」が観測できるが、
これは **正常に走り、正常に緑を返す**。誰も疑わない。

## 実測 5件

### ① `grep -E` は PCRE 否定先読みを解さない (AC-10a)

```
$ echo "require('lodash')" > /tmp/t.js
$ grep -E "require\('(?!node:)" /tmp/t.js ; echo "exit=$?"
exit=1                                    ← 見逃した
$ grep -P "require\('(?!node:)" /tmp/t.js ; echo "exit=$?"
require('lodash')
exit=0                                    ← 検出した
```
**守る対象**: npm 依存ゼロ(NFR-02)。**この門は永久に緑だった。**

### ② `grep -c $'\n\n'` は空パターンに退化する (AC-09d)

```
$ printf 'data: x\n\ndata: y\n\n' > /tmp/sse.txt
$ cat -A /tmp/sse.txt
data: x$
$
data: y$
$
$ grep -c $'\n\n' /tmp/sse.txt
4                    ← 全行数。期待は 2
$ wc -l < /tmp/sse.txt
4                    ← 一致 = パターンが空に退化した証拠
```
**守る対象**: SSE のイベント終端(FR-09)。**終端が壊れても永久に緑。**

### ③ `/usr/bin/time -f` がこの機に存在しない (AC-N01a)

```
$ ls -la /usr/bin/time
ls: cannot access '/usr/bin/time': No such file or directory
$ time -f "%e" echo x
/usr/bin/bash: line 4: -f: command not found     ← 組み込み time は -f 非対応
real    0m0.024s
```
**守る対象**: 同期経路 1 秒未満(NFR-01)。**そもそも走らない。**

### ④ 期待値が別のものを数えていた (AC-22b)

```
$ node graph/gauge.js ledger | grep -cE "^  [0-9]{4}-"
10                                        ← 実測
$ ls ../paradise-creations/*/conclave.json | wc -l
5                                         ← 要件が期待値に書いていた数
```
`gauge ledger` は**追記型**であり、走行のたびに増える。
conclave.json の件数(5)と取り違えていた。
**さらに固定値を期待値にすること自体が第29条の罠である** — 明日には 11 になる。

### ⑤ ERE では `\|` はリテラルのパイプ文字 (G-05)

```
$ printf 'visual-verify\ncritic.js\n' > /tmp/g.txt
$ grep -cE "visual-verify\|critic.js" /tmp/g.txt
0                    ← 誤り。「visual-verify|critic.js」という literal を探している
$ grep -cE "visual-verify|critic.js" /tmp/g.txt
2                    ← 正
```
**守る対象**: ダッシュボードが visual-verify と critic を通ること(G-05)。
第50条の直接の是正を担う門が、**それ自身の書き方で永久に緑だった。**
※ これは差戻し後に**神官が自力で発見**した。差戻しが効いた証拠である。

## ゆえに立てる則

### 則1: **AC は書いた時点で必ず一度走らせ、赤を見る**

修正前に緑を返す AC は、書いた本人が一度も走らせていない証拠である。
「壊すと赤くなる」を要件に課すなら、**まず今、赤であることを見なければならない**。

### 則2: **正規表現の方言をまたぐな**

| 使うもの | この機での挙動 |
|---|---|
| `grep -E` (ERE) | `(?!` `(?=` `\d` `\b` **不可**。`\|` は**リテラル** |
| `grep -P` (PCRE) | 使える(この機では利用可能を実測済み) |
| `grep` に改行 | **不可**。行指向なので空パターンに退化する |

**迷ったら `node -e` で書く。** node の正規表現は方言が一つしかなく、
`split` で数えれば改行も扱える。楽園は node の上に立っているのだから、
**門も node で書くのが最も方言事故が少ない。**

### 則3: **固定値を期待値にしない**(第29条の一般形)

`10` と書けば明日 `11` になって赤くなる。書くべきは**不変量**である:

- ✗ `ledger の行数が 10`
- ✓ `ledger の行数と gauge が自己申告する件数が一致する`
- ✓ `snapshot の counts.engines と ls graph/*.js | wc -l が一致する`

**数え方が二つあって一致することを見る。** 片方を固定値にした瞬間、
それは第29条が禁じた「生成物の中身への依存」と同じ病になる。

### 則4: **この機に在るコマンドしか使わない**

`/usr/bin/time` は無い。`stat -c` の GNU 依存、`timeout`、`realpath` も疑え。
**計測は node の `process.hrtime.bigint()` で書く** — 楽園が既に依存しているものだけで足りる(第20条)。

## この5件が証明したこと

気づいたのは「**実際に走らせろ**」と命じられた審査官である。
そして差戻された神官が、自力で5件目を見つけた。
