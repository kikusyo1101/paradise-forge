神が命じた:「図の作成依頼があった場合にいま行ったフローをサブエージェントが行えるようにしてほしい。必要であればオーケストレーションを新規で組んでも良い」。

実測したところ、**その道は存在しなかった。**

## 実測された誤着

| 神託 | 着いた道 | 何が起きるか |
|------|---------|------------|
| 「オーケストレーションの相関図を作れ」 | `reform` (engine改修11相) | 「オーケストレーション」が改革の語彙に当たる |
| 「位階の図を描いてほしい」 | `standard` (14相) | **存在しない実装物に向かって build と security を走らせる** |

教主は手で歩き直したので着いたが、**機構としては誤着していた**。道が無いことは
「できない」ではなく **最も似た道が黙って代役を務める** ことを意味し、代役は必ず
どこかで嘘をつく。第32条(創らない願い)が既に一度教えたことの再演である。

道の形（creations の道と違い build も security も持たない）:

```
chart-survey → frame → draft → render → chart-measure → behold
                                     ↘ prove          ↘ verify → reflect → verdict
                                     ↘ docs
```

**`chart-measure`(実ブラウザで測る)と `behold`(人の目で見る)が独立した門として在る**
のが要点である。静的な 9/9 は「図として正しい」しか言わない — 溢れ・字の大きさは
開くまで分からず、意味の破れ(「独立」を主張する箱が枠に触れて独立に見えない等)は
幾何が正しいので機械が咎めない。それを人手の判断に委ねず相として埋めた(第18条)。

## 新しい門が既存の欠陥を5件掘り当てた

宣言された神官と、実際に発令される神官が**黙って食い違っていた**:

| 相 | 宣言 | 実際の発令先 |
|----|------|------------|
| **`security`** | **security-reviewer** | **code-reviewer** ← 最も重い |
| `prove` | tdd-guide | architect |
| `docs` | doc-updater | code-reviewer |
| `ux-review` | ux-reviewer | code-reviewer |
| `assess` | requirements-analyst | auditor |

`security` は第31条がこの神官**だけ**に与えた格上げ(opus/xhigh)を持つ。秘密の
見逃しは BLOCK 級の違憲だからである。宛先が違えば、**その格上げは一度も効いて
いなかった**ことになる。名は在り、主も居て、しかし宛先が違う — どの門もそこを
見ていなかった。

## 配置器の欠陥も二つ

- **5px の折れ** (micro-segment)。後から畳めば終点の真上に来るはずの線がずれ、
  今度は `endpoint-side-direction` で鳴く — 症状を別の症状へ移しただけになる。
  正解は **経路を作る前に席を揃える** ことだった。
- **門が己の残骸で落ちる**。`visual-check` が撒く PNG/JSON が次の走行の入力と
  衝突し、二度目から不定に赤くなっていた。**門が罠であってはならない**(第21条)。
  ただし掃除してよいのは門が自分で作る作業場だけ — 成果物の住処には触れない。

**道が在ることと歩けることは別である**(第49条e)。相を並べただけでは道と呼ばない
ので、conclave の環を最後まで回し、全ドメインが批准され作図専用の結びの言に
届くことを回帰テストで固定した。

図の断罪も壊して鳴ることを確かめてある: 証拠なし→BLOCK、静的のみ→REWORK、
実ブラウザで落ちる→REWORK、事実を写経→BLOCK、全て揃って初めて SHIP。
